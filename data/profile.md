## Задачи, которые интересно рассказать на собеседовании

1. **Непересечение броней стережёт база, а не код.** Ограничение
   `EXCLUDE USING gist` по диапазону времени с расширением `btree_gist`.
   Полуоткрытый интервал, чтобы выезд и заезд в один час не считались
   конфликтом. Отменённая бронь просто выпадает из проверки по условию.

2. **Занятость считается по ресурсу, а не по объявлению.** У врача три услуги
   это три объявления, но один ресурс: запись на 14:00 закрывает время у всех
   трёх. У десяти квартир десять независимых ресурсов. Одна модель на оба
   случая.

3. **Три разные ловушки с часовыми поясами, и все давали ровно минус три часа.**
   Разбор по слоям: клиент переводил время в UTC, админка читала базу своим
   поясом, сессия базы была в UTC. Опаснее всего был случай, где бронь
   сохранялась верно, а подпись врала.

4. **Приоритетная очередь под однопоточный ИИ-сервис.** Он обрабатывает один
   запрос за раз, 23 секунды на объявление, замерено. Три очереди по
   приоритету: кнопка в админке, импорт фида, массовый добор. Общий замок.

5. **Разбор затора очереди арифметикой, а не наугад.** На проде скопилось
   25 668 задач и 16 738 упавших. Расчёт показал: задачи копились 89 часов,
   то есть ровно одна часовая порция, которую крон ставил, не проверяя,
   разобрана ли предыдущая. Вторая течь нашлась замером: приходит 383 задачи в
   час, успевает 155. Импорт ставил задачу на каждое объявление, не проверяя,
   есть ли работа.

6. **Правило «тронул руками, значит текст твой».** Очередь отставала на часы,
   человек успевал отредактировать объявление, а потом ИИ переписывал его текст.
   Проверка поставлена в двух местах: задача не ставится в очередь и
   пропускается при выполнении.

7. **Гонки в заказах решены на уровне запроса.** Списание остатка условным
   обновлением: ноль затронутых строк означает откат заказа. Прежняя схема
   «прочитал, проверил, записал» пропускала двух покупателей последней единицы.

8. **Водяной знак считается от видимой части фотографии.** Приложение вписывает
   фото в окно постоянных пропорций и обрезает лишнее, поэтому знак, посчитанный
   от файла, убегал за край. Рядом хранится чистая копия на приватном диске, из
   неё знак пересобирается на всей базе в любой момент. Прогон на проде: 16 397
   фотографий, 65 588 файлов, падений ноль.

9. **Пятисотки с пустым телом разобраны до первопричины в обвязке.** Пустое тело
   значит, что PHP умер до старта фреймворка. Все случаи легли в два окна по
   несколько секунд, совпавшие с выкатом в живую папку. Вторая причина: предел
   в пять процессов php-fpm на весь бэкенд.

10. **Лог на 9,8 ГБ и утечка данных в нём.** Логирование писало каждый запрос к
    базе вместе со значениями, то есть телефоны, почты и хеши токенов. Переведено
    в настройку с порогом по времени, канал разбит по дням: 9,8 ГБ стало 94 МБ.

11. **Карта сайта доросла до 28 МБ и выпала из индексации.** Разбита на индекс и
    подфайлы по 25 тысяч ссылок, редкие части лежат готовыми файлами.

12. **Закрытые ручки отвечают пустым 404, а не 403.** Чтобы посторонний не
    отличил закрытую ручку от несуществующей. Та же логика у чужих чатов и
    сообщений.

13. **Вместо автотестов 30 с лишним самопроверочных команд.** Они ничего не
    меняют и запускаются прямо на проде: проверка пересечения броней в
    откатываемой транзакции, проверки товаров, заказов, выгрузок, платежей,
    картинок, входа. Это осознанный размен, о нём можно говорить честно.

## Фронтенд

React, Vue.js, TypeScript, JavaScript, HTML, CSS и SCSS: компонентный подход,
работа с состоянием, интеграция с REST API. Blade и серверные шаблоны для
админок.

На проекте ЛИДЛЕ фронтенд сделан не на них: клиент это Flutter, админка это
Blade. Поэтому React и Vue.js упоминать как умение можно, а приписывать им цифры
проекта нельзя.

## Белый список: только эти технологии можно называть своими

Серверная часть: PHP, Laravel, PostgreSQL, Redis, Elasticsearch, Laravel Reverb,
веб-сокеты, Sanctum, Eloquent, очереди и фоновые задачи, миграции, Blade,
Docker, GitLab CI, GitHub Actions, Linux, Nginx, php-fpm, Supervisor, REST API,
JWT, OAuth, Git.

Мобильная часть: Flutter, Dart, BLoC, GetIt, Hive, Firebase, FCM, веб-сокеты,
deep links, публикация в Google Play и RuStore.

Фронтенд: React, Vue.js, TypeScript, JavaScript, HTML, CSS, SCSS.

Про фронтенд оговорка: React и Vue.js кандидат знает и умеет на них работать,
но на текущем проекте ЛИДЛЕ они не применяются, там клиент сделан на Flutter, а
админка на Blade. Поэтому про них можно писать «работал с», «знаю», «умею», но
НЕЛЬЗЯ привязывать их к проекту ЛИДЛЕ и к его цифрам.

Второй язык: Python, FastAPI, Celery, OpenAI API, Claude API.

Интеграции: ЮKassa, Firebase Cloud Messaging, Web Push, VK ID, выгрузки в
Яндекс (YML, RSS), импорт из внешних CRM по фидам.

ВСЁ, ЧЕГО НЕТ В ЭТОМ СПИСКЕ, называть своим опытом нельзя. Ни Angular, ни
Symfony, ни Yii, ни Bitrix, ни Kubernetes, ни RabbitMQ, ни Kafka, ни MongoDB,
ни Nest.js, ни Prisma, ни GraphQL, ни Go, ни Java.

Отдельно про тесты: автотестов на проекте ЛИДЛЕ практически нет. Писать «пишу
юнит-тесты» или «покрываю тестами» НЕЛЬЗЯ. Честная формулировка: вместо
автотестов сделано больше тридцати самопроверочных консольных команд, которые
ничего не меняют и запускаются прямо на продакшене.

## Чего в опыте нет

Не приписывать: Symfony, Yii, Bitrix, Angular, Kubernetes, RabbitMQ, Kafka,
MongoDB, Nest.js, Prisma, GraphQL, iOS как основной стек, React Native, KMM,
автотесты на проекте ЛИДЛЕ.

Если вакансия требует чего-то из этого списка, честно назвать смежный опыт одной
фразой и не раздувать.
